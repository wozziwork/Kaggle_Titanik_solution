# Titanic: сравнение разных моделей и фичей.

Задача - бинарная классификация на данных соревнования [Titanic - Machine Learning from Disaster](https://www.kaggle.com/competitions/titanic).

Цель - предсказать выживание пассажира (`Survived`: 0 или 1) и сравнить классические модели, бустинги, нейросети и ансамбли, а также проверить, улучшают ли новые признаки качество предсказаний.

## Запуск

Для запуска требуется **Python**. В `requirements.txt` указана CPU-сборка pytorch.

После скачивания репозитория нужно открыть терминал в его корне - папке с `main.py` и `requirements.txt`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

После установки зависимостей для повторного запуска достаточно последней команды.

### Что выполняется при запуске
1. Выполняется 5-fold CV CatBoost, LightGBM и MLPEmb, затем их обучение на всей обучающей выборке.
2. По OOF-предсказаниям оцениваются голосование и усреднение.
3. В консоль выводится общая таблица CV accuracy базовых моделей.
4. Из сохранённых `FINAL_` загружаются CatBoost, MLPEmb и модели для голосования; создаются CSV для Kaggle.

Обучение и инференс настраиваются независимо. При `save_models=False` новые обученные модели не заменяют сохранённые `FINAL_*`, используемые для инференса.

Результат инференса находится в `inference_predicts/`:

```text
predictions_{experiment_name}_{model_name}.csv
```

Каждый CSV содержит столбцы `PassengerId` и `Survived`, чего требуют условия сабмита.

## Данные и EDA

- `data/train.csv` - обучающие данные с целевой переменной `Survived`.
- `data/test.csv` - данные для предсказания; целевые значения не предоставлены.
- [EDA_Titanik.ipynb](EDA_Titanik.ipynb) - исследование распределений, пропусков, корреляций и связи признаков с выживаемостью, с графиками и текстовыми выводами.

Основные выводы:
1) Наиболее заметно связаны с выживаемостью признаки Sex, Age, Fare, Pclass.
2) Пропуски могут быть информативными, однако добавление отдельных индикаторов пропусков не улучшило CV accuracy в моих экспериментах
3) В именах содержатся обращения к пассажирам (Mr, Miss и т.д.) - извлечение этого признака заметно прибавило результат CV.

## Подготовка признаков

- Пропуски заполняются согласно конфигу.
- Для моделей, которым это требуется, числовые признаки стандартизируются.
- Для классических моделей и обычной MLP используется one-hot encoding.
- CatBoost получает категориальные признаки; для LightGBM и XGBoost столбцы приводятся к типу `category`.
- Для MLPEmb категории кодируются индексами и передаются в обучаемые embedding-слои. Индекс 0 зарезервирован для неизвестных категорий.
- Из имени пассажира извлекается обращение `Title`.

Большинство новых признаков в моих экспериментах не улучшили метрику, а некоторые ухудшили ее.

В CV препроцессор обучается только на обучающей части соответствующего фолда. При инференсе применяется сохранённый обученный препроцессор.

Проверенные признаки:

| Признак | Идея | Результат |
|---|---|---|
| `Title` | Извлечение обращения к пассажиру из имени: Mr, Miss, Mrs и др. | Улучшил CV accuracy; оставлен в финальном наборе |
| `FamilySize` | Размер семьи: `SibSp + Parch + 1` | Не дал устойчивого прироста |
| `IsAlone` | Индикатор путешествия без родственников | Не дал устойчивого прироста |
| Комбинация `Pclass` и `Sex` | Взаимодействие класса билета и пола | Не дала устойчивого прироста |
| `Age_is_na` | Индикатор пропущенного возраста | Не улучшил результат |
| `Age_x_sex` | Численное взаимодействие возраста и пола | Не дал устойчивого прироста |
| `Age_sex` | Комбинация возрастной группы и пола | Не дала устойчивого прироста на разных разбиениях |
| `FarePerPerson` | Стоимость билета на пассажира | Не дал устойчивого прироста |
| `Cabin_group` | Первая буква номера каюты | Не дал устойчивого прироста |

## Модели и эксперименты

Бейзлайн - логистическая регрессия. Также реализованы KNN, решающее дерево, Random Forest, CatBoost, XGBoost, LightGBM, MLP и MLP с категориальными эмбеддингами.

В экспериментах с нейросетями проверялись число и размеры скрытых слоёв, BatchNorm, Dropout, функции активации, оптимизаторы, регуляризация, learning rate, размер батча и число эпох. Также проверялись scheduler и early stopping.
В проверенных конфигурациях scheduler не улучшил validation accuracy и validation loss, поэтому в финальной версии не используется. Проверялись: косинусовый, ступенчатый, а также warm-up с последующим косинусовым снижением.

Больше всего подбор параметров помог для MLP-моделей, удалось добиться качества сравнимого с CatBoost и LightGBM, которые хорошо работали даже без тюнинга.
По Kaggle score лучшими моделями оказались MLP с категориальными эмбеддингами и CatBoost. LightGBM составлял им конкуренцию на кросс-валидации, но по итогам уступил.

### Валидация

Используется `StratifiedKFold`; число фолдов и seed задаются в конфиге. В базовой конфигурации - 5 фолдов и seed 67. Основная метрика сравнения - accuracy.

Для voting и averaging используются OOF-вероятности: каждое предсказание получено моделью, которая не обучалась на соответствующей строке. Для оценки стекинга используется вложенная CV: внутренние OOF-предсказания обучают метамодель, затем базовые модели переобучаются на всей обучающей части внешнего фолда и предсказывают его валидационную часть.

### Ансамбли

- **Averaging:** среднее вероятностей CatBoost, LightGBM и MLPEmb с порогом 0.5.
- **Voting:** большинство из трёх предсказанных классов этих моделей.
- **Stacking:** метамодель Ridge на трёх OOF-вероятностях. Также экспериментально проверялась линейная регрессия.
- **Ансамбль пяти MLPEmb:** среднее вероятностей пяти фолдовых моделей; каждая использует свой препроцессор.

## Результаты

CV/OOF-оценка на обучающих данных и Kaggle score приводятся отдельно. Kaggle-результаты ниже взяты из выполненных отправок.

| Модель | CV / OOF accuracy (текущий конфиг, 5 фолдов, seed 67) | Kaggle score |
|---|---|---:|
| Логистическая регрессия | 0.815919 (средняя CV) | 0.76794 |
| KNN | 0.808053 (средняя CV) | 0.75598 |
| Решающее дерево | 0.817030 (средняя CV) | 0.76076 |
| Random Forest | 0.832766 (средняя CV) | 0.77990 |
| CatBoost | 0.837242 (средняя CV; early stopping, patience=80) | **0.78229** |
| XGBoost | 0.841730 (средняя CV; early stopping, patience=80) | 0.76794 |
| LightGBM | 0.832760 (средняя CV; early stopping, patience=80) | 0.77033 |
| MLP | 0.832766 (средняя CV; фиксированные 4 эпохи) | 0.76794 |
| MLPEmb | 0.832747 (средняя CV; фиксированные 12 эпох) | **0.78229** |
| Averaging | 0.830527 (OOF; CatBoost: 95 деревьев, LightGBM: 54 дерева, MLPEmb: 12 эпох) | **0.78229** |

Лучший полученный Kaggle score - **0.78229**. Его достигли CatBoost, MLPEmb, averaging и stacking. В этих отправках ансамбли не улучшили результат лучших одиночных моделей.

## Настройка экспериментов

Все настройки находятся в [config.py](config.py).

| Раздел / параметр | Назначение |
|---|---|
| `general.experiment_name` | Префикс создаваемых файлов и записей в логах |
| `general.train` | Запуск обучения и валидации |
| `general.inference` | Запуск предсказаний из сохранённых моделей |
| `to_train` | Выбор моделей и ансамблей для обучения / оценки |
| `to_grid_search` | Включение поиска по сетке для выбранных моделей |
| `models`, `dl_train` | Параметры моделей и обучения нейросетей |
| `general.train_dl_on_all_data` | Дополнительное обучение нейросетей на всей обучающей выборке |
| `general.save_models` | Сохранение моделей и препроцессоров |
| `general.save_logs`, `general.show_logs` | Сохранение и подробный вывод результатов экспериментов |
| `general.save_oof` | Сохранение OOF-таблицы при эксперименте с ансамблями |
| `paths.OOF_PROBS` | Путь для записи / чтения OOF-таблицы |
| `to_inference` | Выбор моделей и ансамблей для инференса |
| `inference` | Имена сохранённых моделей, загружаемых при инференсе |
| `models.stacking.cv` | Включение вложенной CV стекинга |

### Только инференс

Нужно установить `general.train=False`, `general.inference=True` и включить нужные флаги в `to_inference`. 
Для готовых моделей используется имя `FINAL_название_модели` в разделе `inference`.

### Обучение своих моделей

Нужно установить `general.train=True`, выбрать модели в `to_train` и задать их параметры. Для нейросетей полное обучение включается через `train_dl_on_all_data`. Чтобы сохранить результат, нужно включить `save_models`.

Новые файлы получают имя текущего эксперимента. Чтобы использовать их в последующем инференсе нужно обновить соответствующие имена в разделе `inference`. Флаг `save_models` не переключает инференс на новые файлы.

Для оценки стекинга нужно включить `to_train.stacking` и `models.stacking.cv`. Если CV выключена, Ridge только обучается на OOF-таблице и при необходимости сохраняется.

Итоговая таблица в конце обучения содержит CV accuracy базовых моделей без grid search. Подробные оценки ансамблей выводятся при `show_logs=True`.

## Структура проекта

```text
main.py                 # точка запуска
config.py               # конфигурация
dataset.py              # загрузка данных и создание признаков
preprocessing.py        # препроцессоры и подготовка входов MLPEmb
optimizer.py            # создание оптимизаторов
inference.py            # инференс моделей и ансамблей
artifacts.py            # сохранение и загрузка артефактов, логов и CSV
visualization.py        # графики обучения
EDA_Titanik.ipynb        # EDA и выводы
requirements.txt        # зависимости
dl_models/              # архитектуры MLP и MLPEmb
train/                  # обучение и управление экспериментами
validation/             # CV, OOF, поиск по сетке и оценка стекинга
data/                   # исходные train.csv и test.csv
saved_models/           # сохранённые модели, препроцессоры и logs.txt
oof_probs/              # сохранённые OOF-таблицы
inference_predicts/     # создаваемые CSV для Kaggle
```

Файлы `FINAL_*` предназначены для запуска готового решения. Включённый в репозиторий `logs.txt` оставлен пустым для записей новых экспериментов.
